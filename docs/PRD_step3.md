# PRD 3단계: 사용자 프로필과 레시피 저장

## 1. 배경과 목표

추천받은 레시피는 화면을 닫으면 사라진다. 사용자가 계정을 만들어 마음에 드는 레시피를 저장하고 나중에 다시 볼 수 있게 하고, 자주 쓰는 추천 조건을 프로필에 저장해 둔다. 이 단계는 AI 모델을 새로 쓰지 않는다.

**전제**: 1단계(PRD_step1.md)와 2단계(PRD_step2.md)가 완료되어, 식재료 인식과 레시피 추천이 동작한다.

**목표**
- 사용자별로 레시피를 저장하고 다시 볼 수 있다.
- 사용자별 기본 추천 조건을 저장해 2단계에서 매번 고르지 않아도 된다.
- 앱을 다시 시작하거나 다시 배포해도 저장한 데이터가 남는다.

**범위 밖**
- 레시피 공유, 댓글, 평점
- 관리자 화면
- 저장한 레시피 수정(삭제만 지원)

## 2. 사용자 흐름

1. 처음 방문한 사용자는 회원 가입을 하고, 이후에는 로그인한다.
2. 로그인하지 않아도 1, 2단계(인식과 추천)는 쓸 수 있다. 저장 버튼을 누르면 로그인을 안내한다.
3. 2단계에서 레시피 카드의 "저장" 버튼을 누르면 내 레시피에 저장된다.
4. "내 레시피" 화면에서 저장한 레시피 목록을 보고, 펼쳐서 상세 내용을 보거나 삭제한다.
5. "프로필" 화면에서 이름(닉네임)과 기본 추천 조건을 저장한다.
6. 2단계 추천 화면은 프로필의 기본 조건으로 채워져 열리고, 그 자리에서 바꿀 수 있다.

## 3. 기능 요구사항

### 3.1 회원 가입과 로그인
- 이메일 기반 계정으로 가입하고 로그인한다. 구체적인 인증 방식(이메일·비밀번호, 소셜 로그인 등)은 구현 단계에서 정한다.
- 비밀번호를 직접 다룬다면 평문으로 저장하지 않고 해시로 저장한다.
- 로그아웃하면 사용자 정보와 화면에 남은 결과가 모두 지워진다.
- 같은 이메일로 중복 가입할 수 없다.

### 3.2 프로필
| 항목 | 내용 |
|---|---|
| 닉네임 | 화면 상단에 표시 |
| 기본 요리 종류 | 2단계 3.1의 선택지와 같음 |
| 기본 조리 시간 | 2단계 3.1의 선택지와 같음 |
| 기본 난이도 | 2단계 3.1의 선택지와 같음 |
| 기본 인원 | 1~6인 |

### 3.3 레시피 저장
- 2단계의 레시피 JSON(PRD_step2.md 3.2) 전체를 그대로 저장하고, 저장 당시의 식재료 목록과 저장 시각, 생성한 모델 이름도 함께 저장한다.
- 같은 사용자가 같은 제목의 레시피를 다시 저장하려 하면 "이미 저장한 레시피입니다."를 보여 준다.
- 저장에 성공하면 버튼이 "저장됨"으로 바뀐다.

### 3.4 내 레시피
- 최근 저장 순으로 목록을 보여 준다: 제목, 요리 종류, 조리 시간, 저장 날짜.
- 항목을 펼치면 2단계와 같은 형식으로 상세 내용이 보인다.
- 삭제할 때는 확인을 한 번 더 받는다.
- 저장한 레시피가 없으면 "저장한 레시피가 없습니다."를 보여 준다.

### 3.5 데이터 저장소
- 데이터는 앱 서버가 다시 시작되거나 다시 배포되어도 사라지지 않는 저장소에 둔다. 무료로 배포할 서비스는 재시작 시 로컬 파일이 초기화될 수 있으므로, 이 점을 확인하고 저장소를 고른다.
- 각 사용자는 자기 프로필과 레시피만 읽고, 쓰고, 지울 수 있다.
- DB 접속 정보는 API 키와 같은 방식(`.env`, 배포 환경의 Secrets)으로 관리하고, 코드와 저장소에 넣지 않는다.

## 4. 비기능 요구사항
- 저장소 접속이 실패하면 저장 기능만 실패를 안내하고, 1, 2단계 기능은 계속 쓸 수 있어야 한다.
- 화면 문구는 모두 한국어로 한다.

## 5. 완료 기준
- [ ] 회원 가입, 로그인, 로그아웃이 동작한다.
- [ ] 2단계에서 추천받은 레시피를 저장하면 "내 레시피"에 나타난다.
- [ ] 다른 계정으로 로그인하면 앞 사용자의 레시피가 보이지 않는다.
- [ ] 프로필에 저장한 기본 조건이 2단계 추천 화면에 미리 채워진다.
- [ ] 앱을 재시작한 뒤에도 계정과 저장한 레시피가 남아 있다.
- [ ] 로그인하지 않은 상태에서도 식재료 인식과 레시피 추천을 쓸 수 있다.
