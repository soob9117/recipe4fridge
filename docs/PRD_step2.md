# PRD 2단계: 인식된 식재료로 레시피 생성

## 1. 배경과 목표

1단계에서 확정한 식재료 목록을 AI 텍스트 모델에 보내, 그 재료로 만들 수 있는 레시피를 추천받는다.

**전제**: 1단계(PRD_step1.md)가 완료되어, 사용자가 확인하고 편집한 식재료 목록(`name`, `quantity`, `category`)이 있다.

**목표**
- 가지고 있는 재료를 최대한 활용하는 한국어 레시피를 받는다.
- 레시피마다 부족한 재료가 무엇인지 한눈에 보인다.
- 사용자가 간단한 조건으로 추천 결과를 조정할 수 있다.

**범위 밖**
- 레시피 저장과 프로필(3단계)
- 요리 사진 생성, 영양 성분 계산, 장보기 목록 연동

## 2. 사용자 흐름

1. 1단계에서 확정한 식재료 목록이 화면에 보인다.
2. 사용자가 필요하면 추천 조건을 고른다(선택 사항).
3. "레시피 추천" 버튼을 누르면 진행 중 표시가 나타난다.
4. 추천이 끝나면 **식재료 목록과 같은 화면에서** 레시피가 보여, 사용자가 재료와 레시피가 맞는지 비교할 수 있다.
5. 사용자는 레시피를 펼쳐 상세 조리 순서를 본다.
6. 마음에 들지 않으면 조건을 바꾸거나 "다시 추천"을 눌러 새 결과를 받는다.

## 3. 기능 요구사항

### 3.1 추천 조건 (모두 선택 사항)
| 조건 | 선택지 | 기본값 |
|---|---|---|
| 요리 종류 | 상관없음, 한식, 양식, 중식, 일식, 간식·디저트 | 상관없음 |
| 조리 시간 | 상관없음, 15분 이내, 30분 이내, 1시간 이내 | 상관없음 |
| 난이도 | 상관없음, 쉬움, 보통, 어려움 | 상관없음 |
| 인원 | 1~6인 | 2인 |

### 3.2 레시피 생성 (AI 텍스트 모델)
- 기본 모델: `cohere/north-mini-code:free`
- 예비 모델(앞 모델이 실패하면 차례로 시도): `nvidia/nemotron-3-super-120b-a12b:free`, `openrouter/free`
- 한 번에 레시피 3개를 추천받는다.
- 프롬프트에 아래를 명시한다.
  - 모든 값을 **한국어로** 작성한다(시험에서 지시가 없으면 영어로 답하는 경향을 확인함).
  - 가진 재료를 최대한 쓰고, 부족한 재료는 소금, 간장 같은 기본 양념 외에는 최소화한다.
  - 사용자가 고른 조건을 따른다.
  - 아래 JSON 형식으로만 답한다.

```json
{
  "recipes": [
    {
      "title": "대파 달걀볶음밥",
      "summary": "남은 밥과 달걀로 10분 만에 만드는 볶음밥",
      "cuisine": "한식",
      "time_minutes": 15,
      "difficulty": "쉬움",
      "servings": 2,
      "used_ingredients": [{"name": "달걀", "amount": "2개"}],
      "missing_ingredients": [{"name": "밥", "amount": "2공기"}],
      "steps": ["대파를 송송 썬다.", "..."]
    }
  ]
}
```

- 앱은 응답을 파싱할 때 ```json 코드 블록 감싸기를 벗겨 내고, 필수 항목(`title`, `used_ingredients`, `steps`)이 빠진 레시피는 버린다.

### 3.3 결과 표시
- 레시피마다 카드로 보여 준다: 제목, 한 줄 요약, 조리 시간, 난이도, 인원.
- 카드에 "가진 재료"와 "부족한 재료"를 나눠 표시하고, 부족한 재료는 눈에 띄게 구분한다.
- 카드를 펼치면 조리 순서가 번호 목록으로 보인다.
- 식재료 목록이 비어 있으면 추천 버튼을 비활성화하고 "식재료를 먼저 추가해 주세요."를 보여 준다.

### 3.4 오류 처리
1단계(PRD_step1.md 3.4)의 규칙을 그대로 따른다. 요약하면:
- 429, 404, 5xx, 시간 초과, `choices` 없는 HTTP 200은 재시도하고 예비 모델로 넘어간다.
- JSON 파싱 실패 시 같은 모델로 한 번 더 요청한다.
- 모든 모델이 실패하면 실패 사실과 원인을 정직하게 보여 준다. 쓸 수 있는 레시피가 하나도 없으면 빈 결과를 성공처럼 보여 주지 않는다.

## 4. 비기능 요구사항
- API 호출 코드는 1단계와 공유한다. 재시도, 예비 모델 전환, 응답 검증을 한곳에 구현해 두 단계가 함께 쓴다.
- 추천 중에는 버튼을 비활성화해 중복 요청을 막는다.
- 어떤 모델이 결과를 냈는지 화면 한쪽에 작게 표시한다.

## 5. 완료 기준
- [ ] 1단계에서 인식한 식재료로 한국어 레시피 3개가 나온다.
- [ ] 식재료 목록과 레시피가 같은 화면에 보인다.
- [ ] 레시피마다 가진 재료와 부족한 재료가 구분되어 보인다.
- [ ] "15분 이내"를 고르면 조리 시간이 15분 이하인 레시피가 나온다.
- [ ] 기본 모델이 실패하면 예비 모델로 넘어가고, 모두 실패하면 실패 안내가 보인다.
